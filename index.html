What is Github?

Github is an online that stores computer code and helps developers work together on software. Basically, it's Khan Academy, but many more perks. On Khan academy, you can edit anybody's code. But you cannot import it to other platforms.

Be sure not confuse it with Git, as I did. Git fetches and runs programs on your computer and on the web. Github is that Hub for Gits. Big difference.

(keep reading for more info)

Why Use Github?

Github is great because

  • It's free (like Khan)
  • You get your own webpage on the internet with a good URL (and even pay for a custom one)
  • There are less restrictions (such as images, link, or audio)
  • There are some tools that aren't fetured on Khan Academy (debuggers, etc)
  • You get fullscreen games (yay!)
  • You get logs so you can pinpoint when exactly a bug came up and see the difference between that code and yours right now
  • Better AI tools (if you're into that)
  • ES6 features (see here)
  • Jsdelivr uses Git so if you want to import your own games/fonts/functions/engines, you pretty much need Git (which is sort of different from Github)

    • The Journey From Khan to Github

    First, you need to know that Khan Academy PJS is different from normal JS. Espiscially ES6 JS. Khan Academy uses a user-friendly (and outdated) version of ES5.

    I will do my best to list the key differences between the two. If you have any questions, look them up or ask me.

  • Khan has a TON of functions that don't usually show up in normal JS, such as ellipse(), rect(), background(), getImage(), and getSound(). In JS, you basically have to code these yourself.
  • Khan pretty much uses var all of them time. let is a different version of var. const means constant. const cannot be overruled or changed. Try
    const f = 2; f ++.
    You will see it does not work. But these are great when you don't want to change something accidently, like gravity or something.
  • Math. is a pretty big one. Khan has built in math functions like round(), trig, PI, and sqr. These are all degree friendly.

    In normal JS you have to put a Math. in front of everything. They pretty much work the same except trig always returns radians, not degrees. The main difference is Math.round(). This returns a float (random number) between 0 and 1, such as 0.2893957. Multiply Math.random() by whatever max number you need and boom!

    Here's a good function:

    function random(min, max) {
     if (arguements.length === 1) {max = min; min = 0;} if (max < min) {return NaN;} return (Math.random() * (max - min)) + min;
    }
    // This works the same as on Khan


    Making a degree to radian converter might be helpful too.
  • Don't even get me started on mouse and key handling. You'll have to figure that out yourself.
  • You'll also be coding inside <html> stuff, so you'll need to type your JS inside <script></script> tags.
  • If you really like Khan Academy's nice functions, you can use @MushyAvacado's Program Exporter. But this does mean less CPU power.

    • Setting up Github

    1. First, you need to make an account. Go here to start.
    2. Next, on github.com find your profile picture. It's in the top right. From there, move two spots to the left, landing your mouse on "All repositories" (a little book icon)
    3. Click that button or go here.
    4. Now you'll see a green button (in the top-ish right) saying "New Reposatory". Repos are where you store your code an other stuff. So click on the green button or go here.
    5. From to to bottom: choose a name for your repo, (ie, my first project). Fill out a short desription if you want, long desriptions can be put in the READMEs. Keep visibility Public (otherwise you won't be able to acess your project on the web). Toggle README on. Click "Create Repository".
    6. Next to the green code button, there will be a button saying "Add new file." Click that, select "Create New File"
    7. Near the nav bar will be a long list of stuff, like Code, Action, Pages, etc. Underneath that, click on "Name your File". Type in index.html
    8. In the edit section, click on the spot that says "Enter file contents here". Paste in this
      <!DOCTYPE html>
      <html>
       <head>
         <meta charset="utf-8">
         <title>New webpage</title>
        </head>
        <body>

        I am empty, please fill me in with stuff :'( <br>
        Lorem Ipsum

        </body>
      </html>
      or your Khan Academy project that you want to save.
    9. Once you are done typing, click the green "Commit Changes" in the top-ish right. AI Copilot will give a desrition of changes or you can make one yourself. "Commit directly to the main branch" basically means save the project, where Create a new branch for this commit and start a pull request means "Spin-off".
    10. Now, when you want to edit, click the index.html to edit. Above the code, there will be some icons. Click the pencil one to make edits.
    11. Now, all you have to do is make a page. Click on settings (to the right of Insights, <>Code, etc) Here, you can rename your repo to something more entertaining. On the left-ish side of the screen, read down until you find "Pages". Click on that.
    12. You have to choose which branch to go off of. Just pick main. In a few seconds, reload the page and there should be a Your site is live at popup. Click the link and/or press "Visit Site." Now it's on the web!

    ES6 Features/How To

    The main thing in ES6, besides const and let, is arrow functions and classes. Let me begin:

    Arrow Functions

    Arrow (or fat arrows) kinda look like this =>. You can use them like

    // Normal function
    const add = function(a, b) {
      return a + b;
    };
    // Arrow function equivalent (basic)
    const add = (a, b) => {
      return a + b;
    };

    You can also take away the () if there's only one parameter and the return, like so

    const double = i => i * 2;

    // Which is like
    var double = function(i) {
      return i *2;
    };
    // Much Shorter and cleaner

    If you no parameters on multiple parameters, you should use (), like so

    const hello = () => "Hello World!";

    const addEm = (a, b) => a + b;
    // Short and to the point

    If the functions only has a single expression (or line) you can remove the {} and the return, like so

    const multiply = (x, y) => x * y;

    With objects, it's a little tricky, try to figure it out

    const makeUser = (name) => ({userName: name});

    // Pretty much the same thing as
    var makeUser = function(name) {
      return {userName: name};
    };

    Try to avoid using => on OOP or anything with the new keyword. Not sure why, but I think is has to do with it not inheriting this like normal functions do.




    Strings and Backticks

    This is in my opinion, the most useful feature. Previously, any strings were sloppy and looked like

    var word = "string";
    var string = "This is a \n multi-line" + word +"!"
    println(string); // This returns "This is a
    multi line string!

    Backticks organize and clean code so ANYBODY can figure out what it says.

    let word = `string`; // Notice the ` and not "
    let string = `This is a
    multi-line ${word} !`;
    console.log(string); // Returns the same thing. Oh, I forogot to mention console.log. Well, just copy paste this into a JS and you'll see.

    So, basically, instead of "stuff" + variable + "more stuff" you can just do `stuff ${variable} more stuff`. Get it?

    The great thing about this is that you can organize long lines of JS string without using \n, plus-es, or anything else that looks strange.

    Define (Basic)

    // Normal OOP
    function Person(name, age) {
     this.name = name;
     this.age = age;
    }
    // Methods added to the prototype manually
    Person.prototype.greet = function() {
      console.log(`Hello, my name is ${this.name}`);
    };

    // Classes
    class Person {
     constructor(name, age) {
        this.name = name;// Like normal
        this.age = age;
      }

     // Methods are written directly inside the class body, not outside like normal OOP
     // This is a functions, by the way
     greet() {
        console.log(`Hello, my name is ${this.name}`);
     }
    }

    Inheritance

    You might not know much about this. I don't really

    // Normal OOP
    function Employee(name, age, jobTitle) {
      Person.call(this, name, age); // Inherit properties
     this.jobTitle = jobTitle;
    }

    // Inherit methods
    Employee.prototype = Object.create(Person.prototype);
    Employee.prototype.constructor = Employee;

    Employee.prototype.work = function() {
     console.log(`${this.name} is working as a ${this.jobTitle}`);
    };

    // Classes
    class Employee extends Person {
     constructor(name, age, jobTitle) {
       super(name, age); // Calls the parent constructor (Person.call)
       this.jobTitle = jobTitle;
      }

     work() {
       console.log(`${this.name} is working as a ${this.jobTitle}`);
     }
    }

    Static Properties/Methods

    // Normal OOP
    function Person() {}

    Person.species = "Homo sapiens"; // Static property
    Person.createAnonymous = function() { // Static method
     return new Person("Anonymous", 0);
    };

    // Classes (make sure to use the static keyword)
    class Person {
     static species = "Homo sapiens";

     static createAnonymous() {
       return new Person("Anonymous", 0);
     }
    }
